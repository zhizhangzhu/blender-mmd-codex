## 先读结论，再选工具

下一轮优先做一套可控制的“人物灯光与材质试验台”：逐层看底色、形体分色、真实遮挡、接触、高光与局部亮边，再回礼堂判断融合。继续叠一层泛光、统一提亮或新增插件，不能替代这套检查。

当前可继续使用已验证的Blender 5.2.2 EEVEE与MMD Tools链路。Goo是一条独立研究路线，鸣潮预设也是待适配的输入系统；二者不能仅靠追加节点组升级为生产默认。优先级及可复用入口见下文。

## 证据和参考如何使用

本次复审读取了人物相关旧笔记、当前节点生成脚本、最新交付JSON及鸣潮发丝输入报告；再次查看了最新4290帧、Gosari《Pretty Girl》2.867秒和《亲亲小狐狸》19.500秒本地原帧。只是指定帧审看，不是新取得B站字幕或看完作者的所有教学。来源与读取范围见 [人物资料账本](research/CHARACTER_SOURCE_LEDGER.json)。

Gosari这张参考中能看到：深发色保留体块与分束亮带，明亮白衣仍有偏冷的形体暗部，眉眼与浅肤色明确分开。小狐狸这张参考则以较强舞台色、人物亮边和斜向地面投影建立空间。应分别制作“明快的角色展示”和“舞台表演”的目标图板，不把两张不同画面平均成一种平光。

同一角色、姿态、相机、显示变换的A/B用于检验实现；不同角色的参考用于比较线条、层次、明暗职责与焦点，不做像素误差或相似度百分比评分。单张图不能反推出作者的灯数、焦距、法线或引擎。原观察见 [Gosari](GOSARI_REFERENCE.md)、[观海子](GUANHAIZI_REFERENCE.md)。

官方资料支持的是设计原则：[Kuro在Epic的采访](https://www.unrealengine.com/developer-interviews/exploring-the-post-apocalyptic-charm-of-asg-open-worlds-in-wuthering-waves)强调人物独立照明应与环境匹配，渐变也依赖美术制作的底色／遮罩，特定表演脸影还需要专门设计。这不提供可照抄的Blender参数。原神GDC2021 PDF仍返回403，仅有索引线索，不在此当作已读完整技术演讲。

## 人物“自发光打光”拆成七个职责

Emission可以作为算完NPR颜色后的输出，关键是输入颜色由什么计算。把贴图直接送进恒亮Emission，只会得到不响应外部灯光的底色；要保留角色可读性，同时保留方向、遮挡和材质层次。[Blender Emission说明](https://docs.blender.org/manual/en/4.4/render/shader_nodes/shader/emission.html)介绍该节点的无阴影表面输出性质；本机实际链路还必须以5.2实测为准。

| 层 | 应控制的内容 | 单独检查时关闭什么 | 常见失败 |
| --- | --- | --- | --- |
| 既有颜色与透明 | PMX颜色、图集、球面乘算／加算、叠层与Alpha | 新增受光、高光、Glow | 把MMD已合成的颜色误称纯Albedo；重建时丢掉球面／透明造成黑块 |
| 形体分色 | 法线、头部轴、主光方向、部位色带、必要的美术渐变 | AO、投影增量、镜面和后期 | 一个色带套所有部位；衣物、头发和皮肤一起变塑料 |
| 几何遮挡 | 刘海到额头、下巴到脖子、手臂到身体的真实投影 | 关闭投影做同帧对照，保留SDF | 用AO或SDF冒充所有发影；提高亮度下限抹掉遮挡 |
| 接触／内凹 | 小范围指缝、领口、关节、鞋底层次 | 全局压暗与长投影 | 大半径AO把脸／白衣涂脏，或黑脚片粘在抬起的鞋底 |
| 材质高光 | 发束亮带、布料宽光泽、金属清楚的反光形状 | Glow与曝光补偿 | 所有材质用同一白色亮点；已有绘制高光再叠一遍 |
| 辅助光色 | 主体补光、色温、逆光、环境色联系 | 分别关闭每组辅助光 | 360度亮边、脸整片发白、人物在任何场景颜色都相同 |
| 真正发亮与光晕 | 首饰／特效的发光、少量高光溢出 | 分开看发光源与合成Glow | 用Bloom伪装材质；眼睛、线条和皮肤一起起雾 |

目标结构可概括为：既有颜色 × 设计好的形体与环境受光 × 受控遮挡／接触 + 按材质限制的高光／辅助光，再通过透明与显示变换输出。**这是整理后的设计约定，不代表现有图已经拆成七个独立生产组件。** 既有节点中有多轮相乘／混合，改动前须追踪真正连到输出的路径，避免重复计入阴影。

## 每个新角色先做输入审计

1. 用 `genshin_character_probe.py` 核对材质、UV、图片、Morph、骨名、描边权重；在材质映射表中明确脸、身体皮肤、虹膜、眼白、眉睫、嘴内、头发、布料、毛领、皮革、金属、透明叠层。中文材质名是线索，不能成为唯一判断。
2. 每张贴图记录路径／哈希、色彩空间、Alpha模式、实际使用通道与使用节点。数据图按真实语义处理；`CHANNEL_PACKED`是Alpha解释方式，和Non-Color／sRGB是两件事。
3. 确认哪些亮部／暗部已经画在底图或球面里。当前 `MMDShaderDev.Color` 保留了原有颜色合成，并非自动分离出的原游戏无光照底色；保留它能避免丢语义，但新增照明应防止重复上色。
4. 遇到缺图，选择明确的手工适配／新制美术遮罩，并标注来源。不能把颜色阈值生成的金色候选当成原始金属度，也不能把颜色图改名Lightmap补齐依赖。

阿克西妮娅已有模型自带FaceLightmap及部分身体／头发Lightmap；空未找到配套游戏身体／头发Lightmap，目前仍包含MMD图集与社区Boy面部模板适配。两者不具备同等输入，不能把同一份控制图路径替换后就称为完成同级适配。细节见 [原神预设研究](GENSHIN_CHARACTER_AND_PRESETS.md) 和 [材质精修](SURFACE_REFINEMENT.md)。

## 脸部：SDF、法线与真实投影各做自己的事

SDF负责美术设计的脸部明暗边界，不会独立感知一束头发此刻遮住了灯。真实投影负责几何关系，但直接把面部几何漫反射硬分段，会把鼻口凹凸放大成不合适的斑块。两条链应能单独检查，再按镜头设计组合。

当前可复用的已验证做法是：保留各自适配的SDF；用随头部前向转动的平整Diffuse探针法线接收几何遮挡，身体仍保留表面法线。平整的是**受光探针的Normal**，不是抹掉模型全部法线、蒙皮或Morph。当前版曾在 `production-v2` 出现下脸斑块，`production-v3` 改用上述方式；不要把弃用实验当作更高级默认。

继续制作时依次检查：

- 头部前／上／右轴在世界空间是否随真实头骨运动；模型局部轴不同，不能统一认定局部Z就是前。当前Face Factor适配的incoming光向与自有FaceLightmap的toward-key约定不同，不能统一再取反。
- SDF左右镜像、UV与角色模板是否吻合。阿克西妮娅曾因通用Lady模板不匹配而出现不合适的鼻眼亮区；已有本模型FaceLightmap时应优先核实它，而非强套模板。
- 关闭投影仍保留SDF；再打开投影检查刘海、脖颈与手靠近脸的遮挡。关闭AO后复查，防止把接触污渍当发影。
- 正面、左右三分之四、侧脸、仰俯头及表情极值都要看；眼睛／眉睫的图形清晰度不能靠让整张脸免疫阴影来维持。

**当前替代链路的边界：**`白色Diffuse → Shader to RGB → 灰度 → MapRange`测到的是综合受光，含法线、衰减、各盏灯与间接受光，不是纯粹的“主灯可见性”或独立shadow pass。当前0.18–0.28阈值和0.68等下限仅针对该场景标定；加一盏柔光便可能让大面积响应饱和。先锁人物灯组的功率／尺寸／链接，再跨固定测试集选区间；不能逐帧用百分位自动归一化，否则可能产生亮度呼吸。后续P0应研究更明确的主光控制／遮挡分离，而不是继续任意叠灯。

[Blender的Shader to RGB文档](https://docs.blender.org/manual/id/5.3/render/shader_nodes/color/shader_to_rgb.html)明确提示它是EEVEE的NPR转换，与若干后期／阴影及pass存在组合局限；这里读取的是5.3手册，不能替代本机5.2的测试记录。现有AOV用来测指定节点信号，不等于获得完整游戏G-Buffer。

## 头发：先整理体块，再设计亮带

按“整体体块明暗 → 分束高光形状 → 发丝细节 → 透明和描边 → 少量局部溢光”的顺序制作。先关闭球面／手绘亮部之外的新增高光，在灰色试验环境看法线是否产生破碎、反向或接缝；再逐层加回。用代理体平滑法线是可研究方向，不能在未检查形态键／蒙皮前覆盖原法线。

高光应与发型、视角和指定光向有可解释的关系，避免整个头顶只剩一块白塑料。当前原神路线有头部轴驱动的分析式亮带、图集限制与小强度预设高光，但没有完整重建原游戏各向异性或鸣潮头发系统。两套高光同时开启时，先确认不会互相叠成白块。

鸣潮HM／HN必须按**实际节点运算**解释：本地 `hair高光(wuwa3.0).blend` 的HM输入连接 `_HN` 文件，HN输入连接 `_HM` 文件，两份发材质一致。复查 `hair-study.json` 已确认这一点，不根据名字擅自交换。原设置包含sRGB／Non-Color与STRAIGHT／CHANNEL_PACKED的不同组合，必须分别记录。

目前只在该预设自带模型上做过原连接、断开HM、断开HN三张静帧；已看到高光形状变化，没有完成当前双人的移植或转头／移灯／绕拍动态验收。移植应先补齐正确的数据或明确制作新遮罩，再用这三项控制测试；把原神Lightmap插进同名口不是一种有证据的升级。[鸣潮研究](WUWA_TOON_STUDY.md)保存了报告、教程OCR范围与复用命令。

## 眼睛、布料与金属的质感验收

| 部位 | 保留什么 | 下一轮必须证明什么 |
| --- | --- | --- |
| 虹膜／眼白／眼线 | 虹膜色阶、瞳孔、边缘、现有透明语义分别控制 | 关闭Glow仍能读出眼睛；转头、眨眼和刘海遮挡不穿帮；眼白不是恒定纯白灯泡 |
| 脸部皮肤 | 适度肤色变化、SDF与真实遮挡，鼻口清楚 | 中性光和婚礼光都不灰、不蜡、不出现几何脏块；亮区保留肤色 |
| 深蓝布料／皮革 | 图案与大形体，克制且较宽的光泽 | 换光向后仍可与金属区分；暗部不靠全图曝光压成黑，不能只按整张服装图集统一金属化 |
| 白布／毛领 | 亮色纹理与彩色暗部、柔和外线 | 关闭Bloom仍有褶皱和体块；不把亮色推成一整片白 |
| 金属／金饰 | 专属遮罩、清楚而有方向的高光与反射形状 | 反射／高光在正确部位，随视角变化；不能用增亮泛白模拟所有金属 |

眼透、深度刘海阴影等属于另外的遮罩与透明流程，要检查双人交叠是否串到另一人物。原神用户预设提供这些接口，不表示当前已经启用其完整效果链。不要为了让眼睛清楚把应在前方的头发全部变透明。

## 黑线：轮廓、结构线与五官线分别设计

当前MMD反壳已经保留PMX材质／顶点权重，并加了有限的距离／焦距补偿；它不是屏幕空间边缘检测。最新相对权重增加头发45%、衣物40%、脸／身体皮肤25%，不是固定像素线宽，也不是对所有角色适用的标准。

外轮廓以人物在最终屏幕中的面积决定可读性；结构线服务衣褶／发束；眉睫嘴是模型或贴图的设计内线。三者不能用统一Solidify裸厚度一起放大。近景需检查睫毛与虹膜、嘴角和发丝缝隙是否粘连，远景需检查轮廓是否被背景吃掉；横竖屏分别审看。

一张线条Cryptomatte全零不能证明画面没有线，修改器存在也不能证明线足够清楚。先做只关反壳的同帧对照，再看100%输出。厚度与边色分开对照；当前“旧线宽”控制保留新边色，不能称为完整旧美术对照。[脸部描边](FACE_INK_REFINEMENT.md)保留了此类失败与证据边界。

## 固定人物试验台与放行标准

以下是下一轮应执行的质量合同；其中原有72帧诊断在旧质量分支通过过，**最新自阴影／加粗版没有重新跑完这套三轴诊断**，不能继承旧结论。新测试统一固定曝光、显示变换、分辨率、背景、采样与角色尺寸；先关闭后期干扰，只有一个变量变化。缩略图看整体、100%看线条与透明，必要时无损逐帧。

| 测试 | 最低范围 | 必须看什么 | 拒绝晋升的情况 |
| --- | --- | --- | --- |
| 固定灯转头 | 前向、左右±35°，至少24个独立帧 | SDF左右、刘海投影、发带与法线一致 | 阴影不随头动、翻面、发带滑动或突然闪烁 |
| 固定头移主光 | 左右±90°，至少24帧，保持功率／距离规则 | 分色范围、投影方向、各材质高光 | 只改功率就整脸跳成一色；错误光向；所有材质同步塑料化 |
| 相机绕拍 | 左右±15°，至少24帧 | 高光视角、描边、透明／眼透与双人重叠 | 高光贴屏幕；脸线破裂；透明串层 |
| 皮肤／头发近景 | 正面、侧面、仰俯头、眨眼、手过脸 | 色块设计、额头／下巴／指缝关系 | 鼻口污斑、眉睫糊掉、厚线吞掉表情 |
| 全身与落地 | 站立、抬脚、交叉步、快转身 | 鞋底接触、投影方向与服饰穿插 | 影子粘在脚底、黑团漂移、为投影改坏原动作 |
| 最终场景与画幅 | 中性试验台、既定婚礼场景；横竖独立 | 人物与场景冷暖、明暗重点、线条尺寸 | 只在中性光好看；靠全局Bloom/曝光救场；裁切充当竖屏适配 |

程序可验证通道有限值、输出帧数、打包、动作相机保持、色彩标签和控制差异；美术放行还要判断脸部是否吸引人、材质是否分开、光色是否服务情绪。出现可疑变化可用光流找候选帧，但不能由运动误差数字自动判定风格或美感达标。最终报告同时记录“技术通过”和“用户美术认可”，两项互不代替。

## 复用入口与操作顺序

1. 先读当前项目配方和输入角色报告，冻结动作／物理／相机。用 `genshin_character_probe.py`、`probe_actor_ink_shadow.py` 检查输入；文件自动执行关闭，继承的File Output先静音。
2. 在新目录测纯颜色／分色／投影／AO／高光／辅助光／Glow开关。`diagnose_actor_light.py`可导出32位受光AOV与材质类别，检查区间是否饱和；它不保存源工程。
3. 针对现有双人接地分支生成新人物候选时，从 `production-v1\Franken_Duet_Grounded_Wedding.blend` 出发调用 `prepare_graphic_self_shadows.py`，另选新参数、新目录。已带 `graphic_self_shadow_revision` 的 `production-v3` 不是这个一次性迁移脚本的再次输入；不要反复叠权重。
4. 用 `render_shader_diagnostics.py` 做三轴连续测试；它建立独立近景相机，检查后不把诊断姿势存回主工程。随后在正式画幅与采样下检查原舞步，不用540p诊断替代1080p线宽验收。
5. 独立重开并运行 `verify_caption_master.py` 对照原动作／相机、贴图和采用的质量预设。再渲五秒全新缓存，合成、检查色彩、连续帧和声音；只有明确的新候选通过，才替换制作项目所引用的配方。
