# 人物受光与材质分层：双人礼堂实测

2026-11-13。对应 `presets/quality/duet-character-layers-v1.json`，输入限定为上一版 Grounded `production-v3`。这是双人横屏五秒的局部改进，不是已达到原神／鸣潮或参考作者质量的认证。

## 这次实际改变了什么

旧人物图经过多轮添加受光、AO、高光，部分空的分析式明暗仍使用常量光向。新链把非五官的主要卡渲输出重新接成：保留 MMD Color → 色彩控制 → 一次材质色带 → 一次短距离接触 AO → 一次头部轴向发丝高光 → 原有 Emission／材质混合／Alpha。

`MMDShaderDev.Color` 保留模型本来的贴图、PMX和球面合成语义，不能叫纯游戏 Albedo。旧节点留在文件中方便回退，但不再叠进新的主要卡渲颜色路径。独立眼睛、眉睫和嘴内保留原设计；嘴缝适配必须逐模型核对真实节点。

受光来自白色 Diffuse 的综合照明。脸用随头部前向的平整探针法线，身体用自身法线；适配的 SDF 与受光先取共同约束，再只进入一次色带。该信号包含灯光、法线、衰减、间接照明与遮挡，不是纯投影通道。不能拿它宣称恢复 Goo 的全部阴影功能。

阿克西妮娅和空的银蓝／金色发带分别设色；高光方向来自实际人物主灯和视向，头部切线跟随姿态。原有金属遮罩和透明输出继续使用，布料和皮革控制少量物理闭包混合。空的眼睛单独调整虹膜饱和度、角膜粗糙度和法线强度。没有伪造空缺少的游戏 Lightmap 或鸣潮 HM/HN。

## 灯光预算与空间关系

每人独立主光 450 W／面积尺寸 0.85，补光 18 W／3.0，轮廓光 95 W／1.6。功率只属于当前比例和距离，不能当其他 PMX 的通用参数。人物主光从前上方斜照，与现有舞台投影的方向呼应。

此前未限定接收者的舞台灯改为只照舞台，重复的人物柔光停用，避免新的主光移动而人物仍由其他高功率灯洗平。美术化 light linking 不代表完全物理照明；地坪、场景、体积与人物仍需各自核实。礼堂、蓝金婚礼主题、局部雾、字幕和指定原声保持同一制作基准。

## 可复查的实际测试

`render_shader_diagnostics.py --neutral` 在独立未保存的场景副本上冻结4200帧，生成三个各24帧、24fps的测试：转头±35°、主灯绕转±90°、相机绕拍±15°。实际输出1280×720，关闭舞台、雾、后期、景深和运动模糊；保留原有骨骼／Morph形成的源姿态。每帧检查头部驱动轴误差与脸部测试区域。

输出位于 `D:/codex/output/MMD-Character-Layer-Refinement-v1/diagnostics-v2/`。这三个测试是刻意施加的受光／视角实验，不替换正式动作和相机，也不证明所有极端动作都已通过。

`render_character_layer_controls.py` 在同一4290帧输出1080p完整图、受光色带关闭、AO关闭、发丝高光关闭、灯光投影关闭。受光关闭只绕过新色带，保留的物理闭包仍响应灯；关闭投影不删除 SDF、形体明暗或已烘焙 GI。不能把这几张图解释为完全独立的物理 render pass。

## 本机执行顺序

1. `prepare_character_layers.py`：限定旧版本输入，在新目录重接主要卡渲颜色、配置灯组、渲染静帧，核对九个时点的动作与相机，再打包并保存新工程。
2. 三轴测试和同帧开关：先看无后期的人物，再看礼堂中最终尺寸的线条、脸眼、衣料、毛领和金属。
3. 原生300帧渲染到新 beauty／actor PNG16缓存；从 RGB 缓存重新编码，避免旧视频矩阵误差混入材质比较。
4. 官方字幕保持整组前后层级；用固定原声FLAC混音，验证完整300帧解码、音轨、色彩和分段接缝。
5. 独立验收报告、实际产物与用户美术反馈分开记录；结果到齐后才更新现行审片与资料库。

最终产物、原生缓存、工程核验和人工抽样范围以本轮交付目录的 `delivery.json` 为准。胸部次级运动单独见 [验证记录](CHEST_SECONDARY_MOTION_VALIDATION.md)，浏览器连通性单独见 [浏览器自主操作](BROWSER_AUTONOMY.md)；没有连接成功不能称读取了登录会话。

## 官方资料与实测边界

本轮实际读到的是官方搜索索引返回的正文片段；以下三页直接打开均返回402，未读取整页或网页插图。资料用于核对职责与限制，最终功能以本机5.2.2实验为证：

- [Blender 5.0 Shader to RGB](https://docs.blender.org/manual/en/5.0/render/shader_nodes/color/shader_to_rgb.html)：EEVEE颜色转换用于自定义着色，同时会脱离标准PBR假设；与阴影／AO等组合仍需实测。
- [Blender 5.0 EEVEE灯光](https://docs.blender.org/manual/en/5.0/render/eevee/light_settings.html)：索引片段确认虚拟阴影贴图与阴影贴图光线追踪的基本描述。本机最终使用5.2.2，不直接把5.0的接口名当现行API。
- [Blender 5.0 Render Passes](https://docs.blender.org/manual/en/5.0/render/layers/passes.html)：Shader to RGB不能被当成可任意拆分的完整物理通道；当前接收遮挡的证据以Combined原生开关图为准。

参考视频的画面观察与实际引擎实现分开：没有取得观海子或Gosari的源节点，也不由单帧推定其灯数、法线或Shader。既有本地视频观察见 [参考学习手册](REFERENCE_AND_LIGHTING_PLAYBOOK.md)。
