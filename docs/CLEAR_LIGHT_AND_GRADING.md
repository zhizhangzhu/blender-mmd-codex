## 灰蒙的诊断与失败样本

`brightness_scene_probe.py` 沿实际输出向上审计节点，再用同一张 HDR 渲染输出不同显示版本。输入为上一版 `production-v5`，实际是 AgX / Medium High Contrast、曝光 0、gamma 1。人物本来已有受控自发光：阿克西妮娅审计的 33 个材质均能沿输出链追到 Emission；空为 24 个中的 21 个，另有透明等专用材质。这是节点链审计，不等于每个像素都是纯自发光，金属／皮革仍有物理混合。

- 同 HDR 的 AgX 曝光 +0.7 会变亮，但主观灰蒙和层次不足仍在；不能只抬曝光。
- 直接切 Standard、沿用旧场景，会使部分地面／饰边过亮；必须重新平衡场景与高光。
- 第一次减少铺满式补光的研究版 `lighting-v2` 整帧亮度反而从约 132 降至 123/255，因此未选作样片；方向更清楚不代表满足“更明亮”。
- 最后提高整理后的窗光与中性间接光，配合受控输出曲线，再渲同镜头比较。亮度统计只是显示值对照，不作为审美得分。

Emission 在这里控制人物表面颜色，前面仍计算法线、明暗、发丝和材质层。静态间接光烘焙隐藏了人物；没有把角色当作照亮整个礼堂的光源。旧版 Fog Glow 节点也不等于真实体积雾，不能只凭名称判灰蒙来源。

## 当前实现

脚本 `scripts/mmd_clear_light_revision.py`；预设 `presets/quality/winter-wedding-clear-light-v1.json`。从旧 `production-v5` 运行一次，输出新工程，不能重复套在已经修订的工程上。

1. 保留原生人物受控自发光与分区材质，调低空在新显示条件下的皮肤／金发饱和度，并校正其皮肤颜色平衡。
2. 关闭旧的大面积非点光灯，使用左前窗主光、右窗暖补光、祭坛顶光和低强度前方反弹四盏灯。人物的解析卡渲／高光方向同步到新的主光方向；窗户和室内光线有明确关联。
3. 世界天空换成较浅的冷蓝／灰白色，建筑额外色乘回到接近中性。原作者的贴图、法线和材质控制继续使用；只把本地加算 MatCap 适配量从 0.65 收到 0.12。
4. 重新烘焙场景静态 GI／反射探针，隐藏移动人物后再烘焙。保留窗外雪点及指定礼堂，不换场景。
5. 使用 `ClearLightActor` 材质 AOV 区分角色和背景。背景中间调做 0.9 次幂调整，人物不随之被整体抬亮；已实际输出并目视核对 4200 帧遮罩，不凭节点存在就判成功。
6. 输出为 Standard / None、曝光 0、gamma 1。显示前按最大 RGB 通道做保色相的平滑高光肩部，knee 0.78、headroom 0.20，低于 knee 的黑位保持；加饱和度 1.04 和很轻的 Glow，避免大面积泛白。

高光肩部是本项目自行实现的美术控制，不是教程作者的原始公式。设中间调处理后的最大 RGB 通道为 m，knee 为 k、headroom 为 h：低于 k 保持；高于 k 用 `k+h*(1-exp(-(m-k)/h))` 平滑过渡，再将比例乘回原 RGB。零黑位保持为零。背景与人物的区别来自实际遮罩；透明叠层和快速运动仍需连续画面验收。

Blender 5.2 本机合成数学节点使用 `ShaderNodeMath`；旧名 `CompositorNodeMath` 不存在。不能照搬旧教程的 API 名称。合成 Hue/Saturation 在本机仍是 `CompositorNodeHueSat`，不能一律替换成着色器节点。
