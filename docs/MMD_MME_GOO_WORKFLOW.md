# MMD MME 与 Goo 分工方案

**后续选择已更新：** 猪猪决定继续使用Goo，并先系统学习其基础功能与参数。下文保留为曾评估的原生路线，不是当前执行方向；现行入口为[Goo基础学习](GOO_FOUNDATIONS_AND_PARAMETERS.md)。

建议先建立原生 MMD／MME 的完整静帧基准，再决定主渲路线。人物卡渲、MME控制器、原生动作和舞台若能在 MMD 中得到更好的结果，就保留在原生环境；Goo负责模型修整、复杂变形／模拟和经过验证的补充工作。当前Goo v6工程保留为对照，不把全部效果再重写一遍，也不立即把人物与背景拆到两个引擎。

## 为什么值得直接用 MMD

原版MME使用自己的效果文件、渲染目标、控制器和绘制顺序。原生运行可以直接检查作者预设的行为，减少当前“读源码后用另一套节点近似”的偏差。[Ray-MMD作者](https://github.com/ray-cast/ray-mmd)明确其实现基于MMD、MME、HLSL和Direct3D9；Goo导入PMX／VMD并不带来同一个执行环境。

不能把多灯、PBR、体积光、景深和Bloom都当成MMD做不到的事：Ray-MMD自身已提供这些类别。对当前需求而言，Goo的价值更多在资产加工、复杂场景管理、变形／模拟与可脚本化诊断，而非效果名称数量。是否更好看仍以当前两个人物的静帧判断。

## 分工建议

| 工作 | 优先路线 | 原因和交接条件 |
| --- | --- | --- |
| PMX、原生VMD、表情、现成相机 | MMD | 保留原生数据和作者工作流；不从已改坏的烘焙反推原始运动 |
| 卡渲基础、脸／发影、描边、轮廓光 | MMD＋一条明确的MME主线 | 先验证作者效果，避免多个主shader覆盖同一材质槽 |
| 舞台材质、光源、粒子和后期 | 先原生MME | 先判断是否已有足够好的实现；Ray另作独立分支，不默认叠在msTC／PowerShader主线上 |
| UV、权重、形态键、网格与法线修整 | Goo，必要时PMX编辑器 | 导出修订PMX前后核材质顺序、日文骨名、Morph、纹理与刚体；复杂Blender节点不会随PMX导出 |
| 果冻眼、复杂纠正形变 | Goo | MMD没有直接对应的几何节点执行器。静态效果可烘成形态；动画必须验证能否表达为骨骼／Morph，不能假设任意顶点变形可写入VMD |
| 特殊衣发／布料模拟 | 原生先试；不足再Goo | 一个镜头选一个物理权威。Goo若回传烘焙，MMD不得再对同一骨链重复求解 |
| 大型程序化场景、特定体积／离线合成 | Goo候选 | 这是工具优势选择，不是宣称MME无同类效果；只有本镜头收益明显才拆层 |
| 字幕、原声与最终编码 | 现有后期工具 | 维持指定FLAC、黑边／投影字幕；当前只看静帧，不输出视频 |

## 三条路线如何选择

### 先试完整 MMD MME

用原始PMX和VMD在新PMM里搭建测试。最初一人一盏主光、固定机位、关闭扩散，确认阴影和材质，再加入指定礼堂。人物与背景在同一渲染环境，遮挡、落地影、景深和透明关系最容易保持一致。若结果更接近参考，就把MMD作为本镜头主渲，Goo只做资产辅助。

### Goo 加工资产后返回 MMD

这条路线最适合作为下一步混合制作方式：[MMD Tools官方说明](https://extensions.blender.org/add-ons/mmd-tools/)支持PMX／VMD／VPD数据进出，但不等于完整`.blend`工程或MME效果可以互转。几何／法线／骨骼／形态的改动先分开回传，材质节点仍在原生MME重新绑定。

先用单个静态姿势做往返：原PMX → Goo修改副本 → 修订PMX／VPD → 新MMD工程重开。检查发型、眼位、材质顺序、Alpha、贴图路径、Morph与刚体。任何关键数据丢失，就保持原PMX主线，仅迁移可验证部分。

动作回传另列实验：原生骨骼与Morph可尝试VMD；任意模拟网格、Geometry Nodes和复杂纠正形变不能承诺自动转换。MMD与Goo的物理不是同一个求解结果。

### MMD 人物与 Goo 场景分层合成

暂不作为首选。两边必须匹配相机投影、时间、尺寸、世界坐标和显示色彩；还需人物Alpha、前景遮挡、落地影、反射和透明的专门通道。普通成图不能恢复完整深度／法线，PNG也不能默认视为带正确Alpha或线性HDR。

如后续确有必要，先只做一张静帧：输出无Bloom的原始层，验证黑／白底边缘或专用Alpha通道，再匹配遮挡与影子，合成后只做一次Bloom／景深。若需要定制MME深度或影子通道，须单独验证，不能把它当作现成可用能力。不要用两张成图简单相加后称跨引擎整合完成。

## 用已有预设建立学习基准

第一轮采用PowerShader主线，因为包已缓存、预设职责清晰：Main、MMD、AllShadow、NoShadow、Toon分别用于基础、原生响应参照、强制全影、无影与硬分段。先看脸／白衣／头发的分色，不叠强柔光。[原作者配布](https://bowlroll.net/file/195743)

第二轮采用msToonCoordinator＋按说明配置的ExcellentShadow，检查ShadeRT、ShadeColorRT、SublightRT和EdgeRT。随包说明要求加载Shade.x、Edge.x、ExcellentShadow.x及控制器；主通道与ShadeRT中的ExcellentShadow开关不同，不能只加载一个`.x`就判断效果好坏。

[msTC作者说明](https://note.com/mashimashi_note/n/n2c2144638054)有一个与当前问题直接相关的限制：Shade_Normal.fx仅用法线求影，不使用ExcellentShadow的投影。它不是让“脸影与刘海投影自动同时更好”的一键选项。先用常规Shade验证发影，再单独研究法线脸影的组合方式。其“SSS”是影色边界的美术处理，不是真实次表面散射。

轮廓光、扩散、色调映射分别增加。そぼろDiffusion的强度与模糊范围独立，说明也提醒默认偏强；[LightBloom](https://github.com/MikuMikuShaders/LightBloom)另有阈值、屏宽比例半径和各层颜色控制。当前伊科尔易过亮，因此先锁基础亮度，再比较一个高亮扩散效果，不同时堆多套Bloom。

## 第一轮可交付的验证

1. 独立MMD／MME环境能启动，MME菜单出现，简单原生模型和材质可加载；记录实际版本，不仅记录磁盘存在。
2. 伊科尔单人固定姿势在无效果、PowerShader、msTC三条独立分支各出静帧，确认真实刘海影、发束暗部、白衣褶皱和眼部高光。msTC缺少兼容的ExcellentShadow依赖时先停留在待配齐，不混用包内变体冒充验证。
3. 加入阿克西妮娅及指定礼堂，保持角色原配色；只逐项改一套参数。保存PMM、MME分配状态和控制器值，独立重开后复现同一张图。
4. 与Goo v6做视觉对照，登记哪种路线改善了哪个问题。当前约定只看静帧；连续动态与视频待用户后续明确要求，再验证物理和闪烁。

先完成第1–2项，再决定是否正式采用MMD主渲。不从“支持格式”跳到“当前全工程可无损迁移”。详细实验卡见[MME原生实验说明](MME_NATIVE_LEARNING_LAB.md)。

## 交接时必须固定的数据

- 以秒为时间基准：`t=(Goo帧-Goo起点)/Goo帧率`，`MMD帧=MMD起点+t×MMD帧率`。两边起点和30／60fps分别记录；落在半帧时不能静默取整，初次先用VPD固定姿势。
- 相机不只对焦距，还核透视／正交、视角、距离、画幅、roll、目标点和投影位置。VMD可导出不保证两边镜头像素完全一致。
- 选择一侧负责物理，另一侧只读烘焙，避免衣发双重求解；未验证的全曲烘焙不带入。
- Goo的色彩管理与MME各效果的线性／显示空间约定分别记录；不要给普通MMD图片直接贴上线性EXR标签。先无Bloom比较基础，再统一一次后期。
- 保留原包版本、SHA、作者、许可、控制器／材质分配与文件顺序。PMM／MME绑定文件和外部贴图一起做便携重开，不假设工程会自动内嵌全部资源。
