2026-11-13复审。目标是让惯性、停顿和碰撞服务于舞蹈、角色与服装，减少橡皮感、高频抖动和穿模。本文整理了现有烘焙证据，并补充官方资料研究；**本轮没有重新模拟、安装插件或产出新的物理样片，胸部动态仍未专门验证**。资料、阅读范围和本机源码指纹在 [来源台账](research/PHYSICS_SOURCE_LEDGER.json)。

## 先选求解路线，再调参数

**当前优先路线：沿用模型原有PMX物理，Blender内模拟并视觉烘焙。** 它已经在本模型和动作上走通，适合先解决衣发碰撞、延迟和稳定性。不要在已清理的最终渲染工程中直接重复Build；从未构建物理的PMX＋VMD导入基线另存副本。

MMD Tools作者明确指出MMD与Blender的Bullet约束行为并不完全相同，胸部尤其可能依赖MMD的软约束；官方推荐MMDBridge作为另一条路线。这是作者说明，不是本仓库的效果验证。[MMD Tools官方已知问题](https://github.com/MMD-Blender/blender_mmd_tools#rigid-body-physics-limitations)

本机 `core/rigid_body.py` 的 `FnRigidBody.new_joint_object` 也保留了该限制说明：同样的“平移下限＝上限”，在Blender硬约束中可能完全冻结本来应有的弹性运动。它提到允许少量活动范围再配合弹簧的近似办法，但不表示任何一组刚度、阻尼能等价复现MMD。**先检查关节自由度，不能只靠加大质量、刚度或求解次数修胸部动态。** [作者刚体实现](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/rigid_body.py)

候选分支均保持“研究，未在本机实测”：

- **MMDBridge**：MMD Tools当前README实际链接到[rintrint分支](https://github.com/rintrint/mmdbridge)。它说明可输出VMD／ABC，并列出与MME不能同时使用的限制；这是独立的MMD侧求解／导出流程，不是把插件装进Blender。未来先用同模型、同动作的小段验证导入、帧率、骨骼／Morph和材质身份，再选择VMD骨骼或ABC几何路线；不要默认ABC还保留原来的可编辑骨骼。[作者使用指南](https://github.com/rintrint/mmdbridge/blob/master/docs/how_to_use.md)
- **Wiggle Bones**：[官方扩展页](https://extensions.blender.org/add-ons/wiggle-bones/)提供骨骼弹性、碰撞和预滚烘焙功能说明。适合缺少可用PMX物理的链条候选，但还没核对本机注册、长链碰撞、后台烘焙及重复结果。不能与已有刚体同时控制同一根骨骼。
- **布料求解或其他弹簧系统**：留作衣物链条明显不足时的专门研究，不把“Rigid Body to Cloth”按钮存在当作一键升级。新增求解器前先证明现有权重、碰撞形状与关节限制确实限制了质量。

## 参数必须连同单位与时间基准记录

本机PMX导入器会缩放位置、刚体尺寸和线性关节限位，质量、摩擦和衰减则按PMX字段传入；所以“模型看起来等高”不等于它们使用了相同物理参数。当前PMX与VMD统一导入scale=0.08，这只是本项目的导入约定，不是MMD到米制的普适常量。本机源码范围见台账的 `core/pmx/importer.py` 与 `core/rigid_body.py`。

位置、尺寸、线性限位与margin先按Blender内部长度数值记录，另记场景单位和换算；若目标明确为米制，报告再同时给出米。角度脚本使用弧度，UI显示可能为度，写入限位前转换，不能将30°直接写成30。质量在SI工作约定下按kg理解，但导入PMX质量是原作者的模拟数值，不是已测定的发束或服装重量；[Calculate Mass](https://docs.blender.org/manual/en/latest/scene_layout/object/editing/rigid_body.html)的密度输入采用kg/m³也不意味着本模型已做过体积／密度校准。角限位及弹簧实现区别参考[刚体约束API](https://docs.blender.org/api/main/bpy.types.RigidBodyConstraint.html)，实际属性仍以本机为准。

| 参数 | 应记录／怎样理解 | 常见误用 |
| --- | --- | --- |
| 空间尺度 | PMX导入scale、根／骨架／刚体的世界变换、场景单位、真实包围尺寸 | 改显示单位或缩放网格后，以为关节、碰撞与重力已同步校准 |
| 质量 | 每一链的分布、根中末端之间的比例 | 用极小质量或极端质量差“加灵动”，造成约束难以收敛 |
| 平移／角阻尼 | 速度和角速度随时间损失的两个控制，分别测试 | 把关节弹簧阻尼、刚体阻尼当成同一个数；全部设为最大 |
| 刚度与限位 | 恢复力度、允许移动／转动的轴、局部坐标轴方向 | 只加弹簧而不约束自由度，或六轴锁死后期待仍有柔性 |
| 摩擦／回弹 | 与哪个碰撞体接触，接触后是否滑动或弹回 | 以高摩擦替代良好碰撞形状，让裙摆粘腿；用高回弹制造假摆动 |
| 碰撞形状／margin | 原始形状、尺寸、间隙、碰撞组与忽略对 | 把Blender默认margin直接抄到细发束，或为避穿模把碰撞体膨胀到推离身体 |
| 时间步 | 源fps、`time_scale`、`substeps_per_frame`、`solver_iterations` | 将子步当作慢动作开关，或只改输出fps改变舞速 |

阻尼语义见[Blender Dynamics手册](https://docs.blender.org/manual/en/4.5/physics/rigid_body/properties/dynamics.html)；限位和弹簧的职责见[Generic Spring手册](https://docs.blender.org/manual/sr/4.5/physics/rigid_body/constraints/types/generic_spring.html)。刚体阻尼与不同弹簧实现的数值范围／算法不能混为一谈；旧教程的“1最稳定”不应默认沿用。

碰撞margin的行为与形状有关，凸形和三角网格不能视为相同；参考[Blender碰撞手册](https://docs.blender.org/manual/id/4.5/physics/rigid_body/properties/collisions.html)。PMX的排除碰撞组也不等价于把每个人物放进一个Blender collection：本机MMD Tools会建立辅助非碰撞约束，误删它们可能同时改变性能与动作。

固定fps和time_scale=1时，子步增加的是每帧内的求解精度，不是动画时长。6子步在30fps下可按约1/180秒的小步长理解，但**不是最终每秒180个独立动作关键帧，也不是输出60fps就自动重算物理**。求解次数主要改善约束收敛，不能修正初始互穿或错误绑定。[Blender Rigid Body World手册](https://docs.blender.org/manual/id/5.0/physics/rigid_body/world.html)

现有双人报告没有完整记录每个刚体的质量、margin、摩擦、重力与碰撞排除表。这是下一轮审计应补的字段，不能用脚本默认值代替当时的实际值。官方[稳定性建议](https://docs.blender.org/manual/id/5.3/physics/rigid_body/tips.html)提醒小而快的碰撞体与缩放会影响稳定性；其版本晚于本机，本文只借用排查思路，不将其界面或数值建议直接写成本机结论。

## 各部位的美术目标与排查顺序

| 部位 | 自然的目标 | 首先检查 | 调参方向与边界 |
| --- | --- | --- | --- |
| 刘海／短发 | 轻微跟随头部加减速，保持脸部可读 | 发根固定、头／额头碰撞体、发束权重、相邻排除 | 优先稳住根部，避免每根发束同相摆动；不可让发束穿过眼睛来制造“轻盈” |
| 长发／辫子 | 根部先动，末端有延迟，转身后逐渐回稳 | 根中末端的关节轴、链长、肩背与手臂碰撞 | 大轮廓先稳定，再调末端；不能把高频颤动当作细节丰富 |
| 裙摆 | 随骨盆和转身展开，步伐时与腿有合理间隙 | 大腿／髋部碰撞形状、裙根自由度、相邻链互碰 | 先修碰撞和关节，再调恢复速度；裙片不是每帧始终贴腿，也不应撑成硬伞 |
| 披肩／披风／飘带 | 起动有滞后，停顿有余势，长度和重量相符 | 肩背、腋下、手套碰撞，固定点与皮肤权重 | 避免一部分顶点被身体和动态骨同时错误拉扯；服装较厚时不追求纸片般飘动 |
| 胸部次级运动 | 服装约束下的短暂惯性与恢复，幅度符合角色和镜头 | 原模型是否有对应骨骼、刚体、权重、类型0/1/2和关节自由度 | 单独研究，小幅、可控；不能拿头发的弹簧／阻尼直接套用，也不靠改造模型体型实现动效 |

胸部路线要先分清骨骼动画、Morph、约束、原生刚体是否已控制同一变形。一次只保留一个模拟来源；如果保留额外动作修正，需要明确混合顺序和影响范围。不能在已烘焙的次级运动上再叠加实时弹簧后宣称“更真实”。本轮没有逐项检查现有两个模型的胸部绑定，不能声称支持或缺失已确认。

## 一轮可复现的制作步骤

1. **冻结输入。** 记录PMX／VMD文件及哈希、模型／动作署名与使用范围、导入scale、源fps、插件版本、IK状态。阿克西妮娅换成Hime后必须重新模拟，旧Hina物理不能复用。
2. **检查原动作与初始姿态。** 先不Build物理审看身体、腿、手和站位；再显示刚体、关节与骨骼叠加，按目标区域分组检查。先修初始互穿、错误父级／局部轴和异常尺寸，再调精度。导入时已严重交叠的碰撞体不会因为更多采样自动变好。
3. **明确IK取舍。** 当前双人脚本会将该源工程的IK约束全部mute；现有报告中每人是四个膝／踝IK。这是本次配布动作的处理，不是通用规则。换动作先读说明并对比原姿态，不盲用同一脚本结果。
4. **做短段基准。** 选择包含起动、急停、转身、抬臂、交叉腿与近身互动的10–15秒源动作，附加预滚和停稳尾段。参考现有6子步／30迭代起点，用同一段A/B；这些数值已走通但不是最优承诺。
5. **顺序求解。** 缓存从预滚起点连续算起，不能直接跳到某帧当作模拟结果。当前全曲脚本将动作整体后移120个30fps源帧，给开头约4秒预滚；它不替代检查第一姿态是否合理，也不自动提供T-pose到起始动作的渐变。若需要渐变，另做副本并记录曲线。
6. **一次只改一类。** 碰撞形状／分组 → 限位与固定点 → 质量分布 → 刚度／阻尼 → 求解精度。每次改参数清理对应缓存后从同一预滚重算；保存实际输入和输出，不能把旧缓存与新参数混记。
7. **烘成便携动画。** 复制身体Action，选择真实被物理驱动的骨骼，视觉烘焙Location／Rotation。输出前比较原模拟和导出骨骼，再停用／移除实时驱动，确认没有双重求解。最后在新进程重开，随机访问已烘焙的时点复查；未烘焙时禁止随机访问验收。
8. **统一时间。** 先按源动作fps模拟，再按明确映射同时变换身体、衣发、Morph、相机的关键点和插值柄。当前60fps五秒的4140–4439是输出时间轴，不能直接当成30fps物理源帧；从项目timebase逆算源段。
9. **先无模糊审查，再回到成片。** 使用固定机位、素色背景、稳定光照、关闭运动模糊检查轮廓和穿模；再用正式近景、景深、阴影与模糊检查可读性。不要用DOF或强运动模糊隐藏不稳定。

烘焙接口入口：双人 `scripts/mmd_duet_physics.py`，单人历史 `scripts/mmd_physics_bake.py`，时间重定时 `scripts/mmd_final_scene.py::retime_actions`。这些是特定输入工程脚本，不能直接对最新60fps便携工程运行。物理缓存的通用原理见[Blender烘焙文档](https://docs.blender.org/UATEST/manual/en/4.5/physics/baking.html)，本机曾遇磁盘缓存切换崩溃，因此已有流程采用内存缓存后导出Action；这不代表所有Blender环境都必须避开磁盘缓存。

## 同动作A/B与验收门槛

下面是后续实验应执行的质量门槛，**不是本轮已经完成的新测试**。固定模型、动作、源帧区间、fps、预滚、相机和光照；A为现有烘焙，B为只改变一组物理参数的新模拟。两版都应输出带帧号的连续低成本预览及原生参数报告。

| 检查 | 必须留下的证据 | 通过条件 |
| --- | --- | --- |
| 起动／急停／回稳 | 连续播放和逐帧联系表，关键链的根／中／末端轨迹 | 有惯性和衰减，无一帧弹飞、持续高频抖动或静止后长时间振铃 |
| 身体与服装碰撞 | 正面、侧面、背面及最终相机；问题帧号 | 不出现可见的大面积贯穿、反折或卡住后突然释放；发现问题不以“平均穿模率低”放行 |
| 权重与约束 | 骨骼／刚体叠加及父子关系表 | 根部稳定，动态部位没有拉长／缩短或错误牵动五官、身体主骨 |
| 烘焙忠实度 | 原模拟与导出动画的指定骨骼矩阵差，包含最剧烈帧 | 误差相对角色尺度足够小且不新增视觉差异；旧脚本0.002只是失败防线，不能作为美术容差标准 |
| 重开／分段一致性 | 独立进程抽样；分段边界连续帧 | 不依赖内存求解、用户GUI缓存或加载顺序；没有重复驱动和分段跳变 |
| 胸部动态 | 明确部位映射、同动作对照、服装约束与幅度评审 | 在上述检查外单独审核；没有部位映射或连续样片就维持“未验证” |
| 最终镜头效果 | 无模糊诊断与正式beauty同时保留 | 物理轮廓与自阴影／描边没有互相放大成闪烁，动作重点与脸部仍清楚 |

数值检测可以标记异常位移、角速度尖峰和持续碰撞候选；它不能单独证明体感“自然”或排除所有网格穿模。禁止给出没有模型尺度与测量定义的统一“胸部摆动厘米值”“发尾回稳帧数”。

## 性能预算与停止条件

现有双人报告：组装到缓存完成约4090秒，包含视觉导出／清理的总时长约4603秒。脚本计时从组装前开始，不能把4090秒称为纯求解耗时；不同模型、碰撞排除数量、CPU和时间步不能直接按比例推算。历史单人有大量辅助非碰撞约束，也不应拿PMX原关节数当作Blender实际约束总数。

后续先对短段计时，分别记录Build、缓存、视觉导出、清理验证、磁盘／内存用量和实际参与刚体／约束数；同时记录一次改动有没有可见收益。没有收益就回退到较低成本配置。若几次增加子步仍反复爆炸，应回查初始互穿、质量差、约束轴与自由度，而不是继续堆到极高采样。小而快的部位先简化碰撞对，所有调整都在副本中完成。

在当前游戏级三渲二目标下，先解决可见的穿模、抖动和过度摆动，再考虑更复杂求解器。良好的次级运动依赖骨骼、权重、动作和镜头共同配合；增加插件数量不等于提升成片质量。
