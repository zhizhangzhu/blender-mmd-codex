# 阿克西妮娅渲染改进：从灰化调色到分区 NPR

2026-11-09，针对用户认为首版质感仍弱于 Gosari542 的反馈，重新读取本地《Pretty Girl》参考帧，在相同动作、物理、相机和姿态下做两轮静帧对照，再输出完整 20 秒新版。以下是本机验证的方法，不是对参考作者节点或参数的还原。

## 学习材料与可采用的结论

- [Ray-MMD 作者的材质说明](https://github.com/ray-cast/ray-mmd/blob/master/Materials/README_chs.md)分别描述皮肤、布料、各向异性和 Toon 模型，以及基本色、光滑度和发光的职责。本次采用的结论是分区控制材质，不能靠全模型同一亮度映射获得不同质感。没有在 Blender 中运行 Ray-MMD，也没有把这些概念等同于作者成片的实际配置。
- [MMD Tools 作者的材质源码](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/material.py)，结合本机 4.5.14 的 `core/material.py` 第 669–762 行：`MMDShaderDev` 除 `Shader` 外，还提供 **`Color` 和 `Alpha`**。`Color` 是基础色、Toon、球面乘算/加算之后的颜色；`Alpha` 保留基础/Toon/球面透明和单双面处理。这是本次解决材质重建问题的关键。上游源码会变化，复用前检查本机节点接口，不能仅凭版本号假设一致。
- 本地参考 `frame-02-02.867s.png`：脸部偏粉白、鼻部阴影轻；眼睛亮但眼线和虹膜轮廓清楚；头发高光呈带状；白衣与紫灰暗部分离。学习目标是这些可观察的画面特征，而非猜测其软件参数。

## 首版的问题

首版保留 MMD `Shader`，转 Shader to RGB 后逐通道执行 `C/(C+0.45)`。这种非线性处理不保留 RGB 通道比例，高亮区尤其容易失去饱和度和对比；本机对照中表现为蓝衣偏灰、银发层次弱、金色配件像米白塑料。提高采样数不会修复这个问题。

此前逐张 diffuse 重建材质曾出现黑色区域。现在验证了另一条有效路线：保留 MMD 节点组的完整输入链，读取其 `Color/Alpha` 输出。没有证明早期黑区的单一根因，因此不将其归咎于 RGB 图片、UV 或 Blender 缺陷。

## 新版节点路线

```text
MMD Color → 分区明暗色相乘 → 分区饱和度/肤色中间调
          → 少量材质高光 → Emission
MMD Alpha → Transparent / Emission 混合 → Material Output
```

主体采用固定世界光向 `normalize(-0.35,-0.65,0.72)`，法线点积经 EASE 色带形成柔化的 Toon 明暗。相机方向与主光方向的半角向量提供少量随视角变化的高光。带状发光仍来自模型已有绘制与球面贴图，未生成各向异性切线贴图。

这是美术控制的 NPR 着色：主体不经过真实灯光的漫反射或投影计算，接触阴影、遮挡与互相反射不等同于 PBR；当前阶段用模型已有绘制细节和受控明暗保持动画画面干净。舞台仍使用 Principled 和实际面积灯。这条路线需要根据目标镜头验证，不能直接泛化为任意灯光环境的物理材质。

分区依据此模型的中文材质名：

| 分区 | 调整目的与本机参数 |
| --- | --- |
| 皮肤 | 粉白、减轻鼻部暗影；阴影色 `(0.96,0.96,1.05)`、亮部 `(1.07,1.10,1.21)`，饱和度 0.8、Value 1.05、Gamma 0.92 |
| 银发 | 保留冷蓝暗部与银白高光；阴影 `(0.48,0.52,0.76)`、亮部 `(0.97,0.99,1.04)`；附加高光指数 42、强度 0.10 |
| 蓝色衣料 | 恢复深蓝与图案层次；阴影 `(0.56,0.57,0.78)`、亮部 `(1,0.99,1.04)`；附加高光指数 70、强度 0.025 |
| 白色毛领 | 单独柔化阴影，避免沿用蓝衣的深色暗部；阴影 `(0.80,0.82,0.94)` |
| 配件 | 保留基础图案和球面层；附加高光指数 90、强度 0.18；这是配件层近似，并非逐像素金属度贴图 |
| 眼睛与眼线 | 眼睛接近均匀受光，保留金色虹膜；眼线单独加深，避免亮眼与淡眼线混在一起 |

数值为线性 RGB 的艺术乘数，允许大于 1；不是从参考图片 sRGB 像素直接抄来的值。`+` 叠层保留原 Alpha 与球面语义，不再重复叠加额外分析高光。没有改变角色的银发、蓝衣和金色眼睛来仿冒参考角色。

舞台 World 强度从 0.65 降到 0.45，原三盏灯分别调至 170/119/297.5 W；背景面板由灰紫改为暖玫瑰灰。人物材质独立后，可以调背景而不把白发与皮肤一起推亮。景深、相机、动作、衣发烘焙均保持首版设置，采样从 48 提高到 96；画面改善主要来自着色，而非采样增加。

## 复现与验证

脚本 `scripts/mmd_look_upgrade.py` 从**首版便携成片工程**开始，不重新导入动作或烘焙物理。它拒绝重复套在已升级工程上，避免灯光多次乘算。保留原 MMD 上游节点，替换旧显示映射，并写入分区/色带属性供手工调整。

```powershell
& 'E:\tools\Blender Foundation\Blender 5.2\blender.exe' --background `
  'D:\codex\output\blender-mmd-codex\aksiniya-final-v001\production.blend' `
  --disable-autoexec --python-exit-code 1 --python scripts/mmd_look_upgrade.py -- `
  --output-dir 'D:\codex\output\blender-mmd-codex\look-upgrade-NEW' --frames 421 661 961
```

本次正式新版工作目录为 `D:\codex\output\blender-mmd-codex\look-upgrade-v003`，前两轮目录留作试验记录。`comparison/` 保存同姿态整体和脸部对照，图片仅排版/等比例缩放，没有图像调色。`look-0421.png` 对应成片 7 秒。另对开眼、闭眼和倾斜姿态作 1080×1920 静帧检查；20 姿态低分辨率工程检查通过（另见 QA 报告）。完整渲染后仍要通过视频解码和音频检查，不能用静帧代替成片验收。

新版与首版六个时点、八根身体/衣发骨骼共 48 组姿态比较，位置与四元数误差为零。报告 `look-pose-verification.json` 对应正式 `look-upgrade-v003` 工程；20 帧图像检查来自画面一致的 `look-upgrade-v002` 静帧版本，报告保留其真实来源路径，不冒称为第三轮重新渲染。

本轮初次长渲染中总显存占用增长、单帧耗时上升；后续检查确认显卡同时运行其他 3D 进程，**不能据总显存值认定 Blender 泄漏**。改用独立进程分段渲染，`render_production.py --start N --end M` 的端点都包含在输出中。合成使用 `assemble_render_chunks.py` 校验范围连续、无重复/缺口和每段尺寸/fps/帧数，再以 FFmpeg 复制视频流。帧范围检查包含空范围、缺口、重叠的测试。

这次中止的单文件 H.264 已编码但尚未写最终 MP4 索引；实际恢复了前 484 个完整图像，随后从工程第 485 帧续渲。恢复段无 B 帧，实际解码得到 484 帧、60 fps；第 484 帧另作源工程静帧核对。该恢复依赖相同编码配置的 SPS/PPS，并非任意损坏视频的通用恢复方法，不作为默认流程。后续优先图像序列，或保存已完成的独立视频段，避免依赖此恢复步骤。最终必须以拼接后全片解码及接缝检查为准。

## 镜头来源澄清

当前成片相机由 `mmd_final_scene.py` **直接在 Blender 创建和写关键帧**，没有制作或导出一份新的镜头 VMD。水瀬ミナ的下载 VMD 作为独立源相机保留，只读取其焦段来影响景别；机位、朝向、跟随方式和竖屏构图由本项目脚本生成。不能把它描述成直接使用作者原镜头，也不能把普通正弦机位运动称为逐镜头复刻。新版保持相机不变，让这轮渲染对照有意义。

## 使用边界

当前分区节点提升了主体颜色分离和干净程度，但仍不是 Gosari542 的同款工程。原模型的眼部绘制、发型、布料贴图和几何决定了可达到的外观；本轮没有重画贴图、建立面部 SDF 阴影贴图、增加逐像素材质掩码或真实各向异性发丝。因此不要声称这些能力已经实现。后续若采用它们，仍按资料学习 → 单项静帧对照 → 连续运动 → 成片验证的顺序记录。
